# Assignment Brief (source of truth)

Ajaia LLC — AI-Native Full Stack Developer take-home. Timebox: **4–6 hours**. A focused partial solution beats an overextended build.

## Scenario

Build a lightweight collaborative document editor inspired by Google Docs. Not a clone — the strongest working slice within the timebox, showing product judgment, full-stack capability and prioritization.

## Required capabilities

1. **Document creation & editing** — create, rename, edit in browser, save and reopen. Rich text: bold, italic, underline, headings/text size, bulleted or numbered lists.
2. **File upload** — at least one product-relevant upload (e.g. `.txt`/`.md`/`.docx` → new editable doc). If file types are limited, say so in the UI **and** README.
3. **Sharing** — a document owner; a way to grant another user access; a visible distinction between owned and shared documents. Simulated users (seeded / mocked auth) are fine.
4. **Persistence** — documents survive refresh; formatting preserved; shared access demonstrable.
5. **Engineering quality** — setup/run instructions; a working deployment reviewers can access; basic validation & error handling; at least one meaningful automated test; a short architecture note.

## AI-native workflow note

Which AI tools were used; where AI materially sped things up; what AI output was changed or rejected; how correctness, UX quality and reliability were verified. *Practical* usage, not volume.

## Walkthrough video (3–5 min)

Main user flow; what works end to end; what was deprioritized; key implementation decisions; how AI supported the workflow. Unlisted Loom/YouTube.

## Deliverables (one Google Drive folder)

- Source code
- `README.md` — local setup and run
- Architecture note (Markdown/PDF)
- AI workflow note (Markdown/PDF)
- `SUBMISSION.md` — exactly what is included
- Live product URL
- Text file with the walkthrough video URL
- Screenshots / demo GIF if setup needs extra steps
- Credentials / seeded users for reviewing sharing
- If partial: what works, what is incomplete, what you'd build next with 2–4 more hours

## Constraints

- Keep scope intentional; depth in a few areas over shallow coverage.
- Any stack; AI tools allowed.
- **Reviewers must not have to pay for any dependency or service.**

## Evaluation

Coherent product slice · full-stack execution (frontend, backend, persistence, access logic) · editing experience quality · file upload & sharing handling · deployment judgment · code clarity & delivery discipline · prioritization & tradeoff awareness · written/verbal communication · mature AI use.

## Optional stretch (only if core is done)

Real-time presence · comments/suggestions · version history · export to PDF/Markdown · role-based sharing permissions.
